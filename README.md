## Возможности

- Регистрация пользователей с выбором роли: игрок или мастер.
- Игрок создаёт и редактирует свои листы персонажей, может закрепить лист за мастером.
- Мастер видит и может редактировать листы всех персонажей, закреплённых
  именно за ним (но не остальные).
- Удалить персонажа может только его владелец (игрок).
- Админ-панель Django (`/admin/`) для полного управления данными.

## Установка и запуск

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate

pip install -r requirements.txt

python manage.py migrate
python manage.py createsuperuser   # опционально, для входа в /admin/

python manage.py runserver
```

Сайт будет доступен на http://127.0.0.1:8000/

## Как это работает

- `accounts/models.py` — кастомная модель пользователя `User` с полем
  `role` (`player` / `master`).
- `characters/models.py` — модель `Character` (лист персонажа) с полями
  `owner` (владелец-игрок) и `master` (закреплённый мастер, необязателен).
  Методы `can_view` / `can_edit` / `can_delete` инкапсулируют правила
  доступа.
- `characters/views.py` — все CRUD-вьюхи используют `UserPassesTestMixin`
  и проверяют права через методы модели, поэтому логика доступа в одном
  месте.
- Форма создания/редактирования для владельца (`CharacterForm`) позволяет
  выбрать/сменить мастера из списка пользователей с ролью "мастер".
  Форма для мастера (`CharacterMasterEditForm`) не содержит поля `master`,
  чтобы мастер не мог переназначить владельца или снять себя с персонажа.

## Структура проекта

```
config/          — настройки и корневые urls
accounts/        — пользователи, роли, регистрация
characters/      — модель персонажа, CRUD, права доступа
templates/       — общий шаблон и шаблон логина
```
